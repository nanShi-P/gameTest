# Refine Requirements — Unity 增量游戏需求细化

## 何时使用
- 用户描述了一个游戏想法但还不够具体（主题、玩法、数值、平台不明确）
- 用户要在已有游戏上加一个大功能模块（如转生、新维度、新货币）
- 现有 `docs/requirements.md` 与用户最新想法已不一致，需要重新对齐

## 工作流

### 步骤 1：检查已有需求
读取 `docs/requirements.md`（若不存在则新建）。如已存在，先向用户确认是"新增"还是"重写"。

### 步骤 2：分组提问（使用 AskUserQuestion，一次问 3-4 个）

按以下五个维度提问，**每个维度只问最关键的 1-2 个问题**，避免轰炸：

1. **主题与基调**：题材（太空/农场/魔法/赛博朋克/抽象数学…）、画风（像素/扁平/3D/纯文本）、目标受众
2. **核心循环**：主资源是什么、第一个生产者怎么获得、第一次"哇时刻"在哪里
3. **进度系统**：层级数量、转生/Prestige 是否要、永久升级形式
4. **必备机制**：离线收益、成就、自动化、事件、随机性
5. **平台与规模**：目标平台（PC/手机/WebGL）、单机/联网、预期游玩时长、是否商业化

### 步骤 3：生成 `docs/requirements.md`

模板：

```markdown

> 最后更新：{{YYYY-MM-DD}}

## 1. 概览
- 主题 / 题材：
- 画风：
- 目标平台：
- 目标受众与预期时长：

## 2. 核心循环
点击 / 初始动作 → 资源 → 生产者 → 自动化 → 解锁下一层

具体描述：……

## 3. 资源与数值
| 资源 | 符号 | 初始 | 用途 |
|------|------|------|------|
| …   |     |      |      |

成本公式：`cost = base * mult^owned`，mult=…
产出公式：…

## 4. 生产者 / 建筑列表
| 名称 | 解锁条件 | 基础产出 | 基础成本 |
|------|----------|----------|----------|

## 5. 升级 / 转生
- 升级类型：
- 转生触发条件：
- 转生货币与永久加成：

## 6. UI 结构
主要面板：……
信息层级：……

## 7. 非功能需求
- 大数支持（BreakInfinity）
- 存档（位置、版本号、加密）
- 离线收益上限
- 性能预算（UI 刷新频率、tick 频率）

## 8. 不做的事（明确范围）
- 例：本期不做多人、不做内购

## 下一步
运行 `/plan-tasks` 把本文档转为开发任务清单。
```

### 步骤 4：交付
- 写入 `docs/requirements.md`
- 简短告知用户文档已生成，并提示运行 `/plan-tasks` 进入下一步

## 重要原则
- 提问时一次最多 4 个，宁可多轮也别一次堆砌
- 数值类问题如果用户答不上来，给 2-3 个常见档位让其选（如转生 mult: 1.5 / 2 / 自定义）
- 范围控制：MVP 优先，把"不做的事"显式列出来
- 不要在本 skill 里写任何代码或开始拆任务，那是下一个 skill 的事
